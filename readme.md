# 阿里天池复杂表格理解方案

## 1. 项目目标

本项目面向“从图片/PDF 中理解复杂表格并回答问题”的天池比赛。输入是 `files/` 下的文档和 `tests.xlsx` 题目清单，输出是与题目 `id` 一一对应的 `submission.xlsx`。

最终目标不是只做 OCR，而是建立“文档 → 表格结构 → 问题意图 → 答案”的完整链路，覆盖：

- 表格结构恢复：单元格文本、逻辑行列、行列位置、横向/纵向合并；
- 表格内容提取：单元格、行、列、区域及多级表头下的字段值；
- 表格内容推理：计数、求和、求差、比例、平均、筛选、排序和简单判断。

比赛要求使用阿里云云端产品，语义识别与多模态推理统一使用阿里云百炼/PAI 上的千问系列模型。本地程序只负责文件预处理、结构化缓存、确定性计算、格式校验和 Excel 导出，不使用非阿里云大模型或人工逐题填写隐藏测试集。

### 2.4 数据质量和兼容性问题

1. 文件名存在零填充差异：清单中的 `58.pdf`、`59.pdf`、`0060.pdf` 对应目录中的 `058.pdf`、`059.pdf`、`060.pdf`。加载器应按“精确文件名 → 去除前导零后的数字 stem → 扩展名”建立安全别名映射。
2. `table_hint` 不是绝对可靠的定位依据：有 243 道题为空，且个别题目提示与问题语义不完全一致。应把它作为候选提示，再用页面标题、问题关键词和视觉定位复核。
3. `tests.xlsx` 的 `answer` 列全部为空，因此本地不能直接计算官方准确率，需要依靠结构校验、交叉一致性和抽样人工标注的小验证集做回归测试。
4. 部分 PDF 没有可用文本层，部分论文 PDF 的文本层存在编码错乱；不能只依赖 `pdftotext`，必须保留高分辨率页面渲染和视觉识别回退路径。
5. 题目中存在“插值/差值”等轻微错字、中文英文混写和多级表头继承，问题解析需要同义词、模糊匹配和单位归一化。

## 3. 总体解题流程

```text
题目清单质检
    ↓
文件名解析、PDF 分页和图像预处理
    ↓
页面/目标表格定位（标题 + table_hint + 问题关键词 + 视觉定位）
    ↓
表格结构解析，生成统一 TableIR 中间表示
    ↓
问题解析为可执行意图（字段、行列、过滤条件、运算、输出格式）
    ↓
字段提取或确定性计算
    ↓
按 answer_format 序列化、校验、写入 submission.xlsx
```

核心原则是“先解析表格，再回答同一文件上的多道题”。同一页/同一表只调用一次结构识别并缓存结果，后续问题通过中间表示查询，减少 API 调用，也避免每道题单独识别导致结果不一致。

## 4. 具体方案

### 4.1 题目加载与路由

读取 `tests.xlsx` 后保留原始行，并生成规范化字段：

- `id`、原始文件名、解析后的实际路径、题型、问题、表名提示、答案格式；
- `file_name` 按别名表解析，解析失败立即进入错误报告；
- `question_type` 只接受 `structure/extract/thinking`，非法值按问题语义和 `answer_format` 推断并记录告警；
- 以“文件 + 页面/表名提示”分组，避免重复上传和重复 OCR。

问题解析输出一个内部 DSL，示例：

```json
{
  "target": ["应收账款", "期末余额"],
  "filters": [{"row_label": "1年以内"}],
  "operation": "select",
  "output": "json_array",
  "precision": null
}
```

`operation` 至少支持 `select`、`count`、`sum`、`difference`、`max`、`min`、`average`、`ratio`、`concat`、`boolean`。大模型负责理解问题和生成候选 DSL，真正的数字运算由本地 `Decimal` 完成。

### 4.2 文档预处理和表格定位

1. PDF 先读取页数和文本层；文本层可用时用于快速找标题、表名和页码，但最终仍用页面图像复核坐标。
2. 文本层为空或乱码时，以 200–300 DPI 渲染页面，并做旋转校正、去噪、对比度增强和大表分块。
3. 原始图片保留原分辨率；小表、长表和密集财报分别采用整页、表格裁剪、局部放大三种输入。
4. 表格候选按 `table_hint`、表题、问题中的实体/年份/字段和页面位置排序；若提示与问题冲突，以视觉内容和字段命中率重新选择。
5. 跨页表格需识别“续表”、重复表头、页眉页脚和单位说明，把多个页面拼接成一个逻辑表，而不是把每页当成独立表。

### 4.3 统一表格中间表示 TableIR

每个目标表保存一份结构化缓存，内部字段比最终答案更丰富：

```json
{
  "title": "表格标题",
  "unit": "人民币元",
  "page_ids": [0, 1],
  "row_count": 8,
  "col_count": 4,
  "cells": [
    {
      "text": "期末余额",
      "row": 0,
      "col": 2,
      "rowspan": 1,
      "colspan": 1,
      "bbox": [0, 0, 0, 0],
      "confidence": 0.98
    }
  ],
  "header_paths": {
    "2": ["资产", "期末余额"]
  }
}
```

其中 `bbox`、置信度和页面信息只用于内部定位与复核，提交时结构题只保留题目规定的字段。表格解析采用“视觉模型识别 + 坐标/边框规则校正”的组合：先确定逻辑行列，再把 OCR 文本放入网格，最后根据边框、背景色、重复表头和跨页关系推断 `rowspan/colspan`。

针对特殊文件增加专用解析器：

- 089：按颜色连通区域和网格切分，再 OCR 编号，不能按普通文字表格处理；
- 090：利用颜色块、行列网格及 `RowSpan/ColumnSpan` 文本恢复合并关系；
- 093：保留等宽字符和 `+|-` 线框，按 ASCII 边界解析，避免 OCR 合并列；
- 010：先识别 Day、时间段、卡片、标签四层关系，再回答跨天筛选问题；
- 财务表：显式保存单位、负数括号、期初/期末、本期/上期和合计行。

### 4.4 千问多模态调用策略

使用阿里云百炼/PAI 上可用的千问视觉模型完成页面理解和表格候选结构识别。建议采用三轮提示，而不是一次让模型直接给最终答案：

1. **定位轮**：只返回目标表所在页、表格边界、表题和候选表头；
2. **结构轮**：要求严格输出 TableIR JSON，禁止 Markdown，要求每个真实单元格只出现一次；
3. **问答轮**：把 TableIR 和单道题的 DSL 交给模型确认语义，输出候选值；数字和数组再由本地程序格式化。

每轮都提供 `question_type`、`table_hint`、`answer_format` 和输出 JSON Schema。对低置信度、跨页、密集小字和合并单元格表进行局部裁剪重试；两次结构结果不一致时，让千问做差异复核，而不是直接随机选择。

### 4.5 三种题型的回答规则

#### structure

最终 `answer` 必须是合法 JSON：

```json
{
  "row_count": 4,
  "col_count": 3,
  "cells": [
    {"text": "项目", "row": 0, "col": 0, "rowspan": 2, "colspan": 1}
  ]
}
```

行列从 0 开始；`row_count` 和 `col_count` 是完整逻辑表的尺寸，即使题目只要求前几行/列；局部题只输出题目要求范围内的真实单元格；合并覆盖位置不输出占位单元格。输出前检查单元格边界、覆盖关系、跨度是否为正整数及 JSON 是否可解析。

#### extract

先根据“行标题 + 多级表头路径 + 单位/期间”定位单元格，再按题目要求返回原始语义值。一个值直接输出字符串或数字；多个值按题目顺序输出紧凑 JSON 数组。不得加入“答案是”等解释。

#### thinking

先完成与提取题相同的定位，再执行 DSL 运算：

- 金额和小数用 `Decimal`，避免浮点误差；
- 中文财报中的千分位、括号负数、破折号空值和单位倍率统一归一；
- 百分比、日期和保留小数位严格服从题目；
- 合计、差值、平均、最大/最小值和筛选均由程序计算；
- 输出是名称列表时保持表中顺序，输出数字时不添加千分位逗号；
- `json_array` 中的缺失值使用空字符串，空答案只在确实无法定位时使用。

这样可以避免大模型在长数字、负数和多步加减中的常见错误。

## 5. 校验和容错

### 5.1 输入校验

- `id` 非空、唯一且保持字符串形式；
- 每个文件都能通过精确名或安全别名解析；
- 题型和答案格式落在允许集合内；
- 记录异常题目、提示缺失、PDF 无文本层和多候选表格。

### 5.2 答案校验

- 输出行数必须为 909（1 行表头 + 908 道题），且不缺 `id`、不重复 `id`；
- 只输出 `id`、`answer` 两列，答案统一写成字符串，避免 Excel 自动改写长数字；
- `json/json_array` 必须可解析，结构题必须具备 `row_count`、`col_count`、`cells`；
- 结构单元格不能越界，合并区域不能非法重叠；
- 数字答案不能含千分位逗号，负数、百分号和保留位数按题意处理；
- 对同一表中“期末 + 期初 = 合计”“明细和 = 小计”“差值方向”等关系做一致性检查；
- 低置信度结果进入复核队列，优先复核跨页表、印章/水印、乱码 PDF、单位变化和合并单元格题。

没有官方答案列可用于本地自动打分，因此建议额外建立一份小型人工验证集，覆盖 001、006、010、058–073、089、090、093 等高风险样本，用于比较不同提示词、分辨率和重试策略。

## 6. 目标结果与交付标准

### 6.1 必须交付

生成 `submission.xlsx`：

| 列 | 要求 |
| --- | --- |
| `id` | 与 `tests.xlsx` 完全一致，908 行，不缺失、不重复 |
| `answer` | 按题型和 `answer_format` 输出最终值；无法作答才填空字符串 |

提交文件不得写入过程日志、置信度或额外列；这些信息另存为内部调试报告。

### 6.2 项目验收目标

1. 格式目标：100% 题目成功落盘，100% JSON 可解析，0 个重复/缺失 `id`。
2. 结构目标：所有结构题满足行列编号、合并关系和局部范围规则。
3. 语义目标：抽取题优先达到稳定高覆盖，推理题通过确定性计算保证数值可复现，最终以官方“正确题数 / 908 × 100”作为唯一成绩指标。
4. 最终目标：在不人工查看和填写隐藏测试答案的前提下，自动生成可直接提交的高准确率 `submission.xlsx`，并保留每题的来源页、候选表、置信度和校验日志以便定位错误。

## 8. 第一阶段已实现的本地工具

第一阶段已落地在 `scripts/`，不依赖 Qwen API：

## 9. 第二阶段：Qwen TableIR 构建器

第二阶段已加入：

- `qwen_client.py`：读取 `.env` 中的 Qwen 配置，使用 OpenAI-compatible `/chat/completions` 接口发送图片和提示词；支持备用模型、JSON 提取、CA 证书配置和显式 SSL 开关；
- `build_table_ir.py`：按文件分组题目提示和相关问题，调用千问视觉模型生成 `table_ir.v1`，并校验行列边界、合并跨度和单元格覆盖冲突；
- schema 失败会带具体冲突信息自动重试一次；模型原始文本保存在 `.raw.txt`，失败信息保存在 `.error.json`，便于复盘。

先用少量样本验证：

```bash
python3 scripts/build_table_ir.py \
  --file 011.jpg --file 078.png --file 090.png --file 093.jpg \
  --max-tokens 10000
```

自动选择 011–057、078–093 的被引用单页图片时，可以使用 `--limit` 控制调用数量；正式批处理前建议先 dry-run 检查提示：

```bash
python3 scripts/build_table_ir.py --limit 3 --dry-run
```

当前已验证 `011.jpg` 英文/中文课程表、`078.png` Amazon 财报、`090.png` 合并单元格表和 `093.jpg` ASCII 表格，均能生成合法 TableIR。模型输出中的单元格重叠会被拒绝并自动重试，不会直接进入后续问答。

## 10. 第三阶段：财务字段归一化与跨页拼接

第三阶段已加入：

- `financial_utils.py`：识别 `in millions`、`in thousands`、亿元/百万元等单位，解析逗号、货币符号、括号负数、破折号空值、百分比和每股数据例外；
- 期间归一化：将 `期末余额/期初余额`、本期/上期和英文年份映射为稳定 period key；
- `stitch_table_ir.py`：拼接页级 TableIR，检测并移除续页重复表头，保留 `source_page`；
- `build_financial_pages.py`：对 PDF 每页调用千问识别目标财务表，再生成拼接后的财务 TableIR。

示例：

```bash
python3 scripts/build_financial_pages.py \
  --pdf 007.pdf \
  --hint '固定资产情况表' \
  --max-tokens 12000
```

该流程已实际验证 `007.pdf` 的两页固定资产表：拼接为 29 行、7 列、137 个单元格，去除第 2 页重复表头，并为数值单元格附加 `raw_value`、`scaled_value`、`period` 和负数标记。财务归一化只增加内部元数据，不覆盖原始文本，后续答案格式化仍可按题目要求选择原始显示值或统一单位值。
